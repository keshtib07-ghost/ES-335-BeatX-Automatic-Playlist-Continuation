How it works

From playlists to ranked tracks.

01

Group and split

We staged 65,464,776 distinct playlist–track memberships. Exact track sets stayed together, and all 20,000 pilot playlists plus their exact copies were assigned to training.

02

Find related tracks

The sparse index uses all 804,485 training playlists. Item–item cosine similarity links co-occurring tracks, and a shrinkage term discounts pairs with few observations.

03

Infer context

One-vs-rest logistic classifiers use word and character TF-IDF. They fit 60,000 weakly labeled titles, then predict tags for all training playlists. Labeled groups contribute track-level evidence.

04

Rerank and test

Plain and tag-aware CF share the same candidates. The title-aware ranker promotes tracks with positive tag lift. Validation chose weight 1 before the held-out test.

Interpretation

Where the model runs out of evidence.

Title coverage

Only 660 of the 5,000 test titles triggered tags. Other queries use the plain CF ranking. The classifier was checked against keyword labels, so agreement measures how well it reproduces those rules.

Unseen tracks

Seven test queries had all three seeds absent from training. Those queries fall back to popularity. There were also 5,922 unseen reference occurrences among 316,437 total.

What the metric measures

The scores measure recovery of held-out tracks. How well the music fits a listener's intent needs a separate study. We used exact Spotify track IDs, so alternate releases may count separately.

Where reranking helped and hurt

Does playback order matter?

Playback flow reorders the same recommendations using adjacent songs observed in training playlists. A separate order-recovery test checks how many original directed transitions it recovers from the same 20 tracks, with the first track fixed.
